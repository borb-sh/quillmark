# 0.114 → 0.115 — a variant cell rests at card level, and an island's line is a `para`

Three changes, one release. A variant-bearing enum stops resting as a container:
the discriminant is the bare string every enum is, and each world's cells are
card-level fields beside it. Then two changes to the content model, both about
the same thing: a fact stored beside an island that the island already carried.

The breaks no type checker reports lead. **A document spelling a variant world
under its enum stops rendering**, and the region and diagnostic addresses of
every variant cell lose their enum prefix. Then **canonical content bytes move.** For
any document holding an island the `loss` key leaves the island form; for any
document holding a table `{"kind":"island"}` becomes `{"kind":"para"}`. A
content hash or cache key computed over stored bytes recomputes once, on those
rows. The storage tag becomes `quillmark/document@0.115.0`, and no stored row
needs migrating: rows tagged `@0.112.0`, `@0.93.0`, `@0.92.0`, `@0.82.0` and
`@0.81.0` migrate forward on read, and a row written with either old spelling
opens here and comes back in the new one. No rendered output moves — nothing
rendered from either fact.

## A variant cell rests at card level

A variant-bearing enum rested as `{value: <member>, …the member's fields}`, one
indentation level below every other field on the card. It rests as its scalar
now, and a variant cell is a card-level field whose *existence* the schema
scopes to a member. `variants:` in `Quill.yaml` does not change.

```yaml
# 0.114
classification:
  value: CUI
  controlled_by: SAF/AA
  poc: Capt J. Smith, DSN 555-1234

# 0.115
classification: CUI
controlled_by: SAF/AA
poc: Capt J. Smith, DSN 555-1234
```

The bare `classification: CUI` was already accepted as the spelling of a world
with no answers; now the answers sit beside it. The container spelling is not
adopted: it is an object where the enum wants a string, so `Quill::validate`
reports `validation::type_mismatch` at `main.classification` and render refuses
it. Sweep stored documents with `validate` — a CUI memo against `usaf_memo`
that still nests is the row that reports it.

### What a plate reads

```typst
// 0.114
#if data.classification.value == "CUI" { data.classification.poc }
// 0.115
#if data.classification == "CUI" { data.poc }
```

**Every declared cell is on the plate on every document.** A live world's cells
carry the document's answers and a dormant world's rest at their blanks — never
the stranded value, never that cell's `default:` — so `data.poc` is total
without a guard and the branch over `values ∪ blank` decides whether the read is
an answer or the blank. Under 0.114 a read outside the branch was a missing-key
error; a plate that relied on that to catch a stray read now gets `""`. An
unanswered discriminant renders `""` and its cells render blank; the
empty-document contract is otherwise untouched.

### Addresses lose the enum prefix

The address of a variant cell is its own name, on both backends and at every
surface that carries one: `session.regions()`, `session.fieldAt()`,
`Diagnostic.path`, `form-field(field:)`, `field-region`, `display`, the acroform
`form.json` binder, `reader.getContentAt`.

```ts
// 0.114
region.field === 'main.classification.poc'
doc.pathFor({ field: 'classification.poc' })
reader.getContentAt(MAIN_CARD_ADDR, 'classification', ['note'])
// 0.115
region.field === 'main.poc'
doc.pathFor({ field: 'poc' })
reader.getContent(MAIN_CARD_ADDR, 'poc')
```

`validation::must_fill` and `validation::out_of_variant` anchor at `main.poc`,
and the enum's own `validation::enum_violation` at `main.classification`, where
the bare-scalar spelling already put it. An enum offers no property step, so
`classification.poc` and `classification.value` are refused wherever an address
is checked.

### A name is one cell of the card

A cell rests beside the card's fields, so its name is unique across the card: a
variant cell named like a card field, or a name two enums' worlds both declare,
is `quill::variant_field_collision` at load whether or not the declarations
agree, and the diagnostic names both owners. Within one enum the rule is
unchanged: every world declaring a name declares it identically. `value` is an
ordinary name now, and `quill::variant_reserved_field_name` retires.

### `$seed` overlays and seeding

An overlay names a variant cell at card level beside its discriminant
(`$seed: { entry: { classification: CUI, note: hello } }`); one nesting the cells
under the enum warns `validation::seed_type_mismatch` at `$seed.entry.classification`.
A seeded card commits the discriminant and the live world's `example:` cells as
separate fields; an overlay cell of a dormant world commits as written and the
card reports it `out_of_variant`.

### The transform schema and `resolve()`

The transform schema projects every world's cells as card properties beside
the enum, in declaration order, instead of under a `classification` object; the
declaration view (`schema()`, `Quill.variants`) is unchanged. `resolve()` reports
one row per cell with its own rung, where the container reported one rung for
the whole thing.

### Rust and WASM

`VARIANT_DISCRIMINANT_KEY` is gone from `quillmark_core::quill` and from the
`@quillmark/wasm` runtime, and `FieldSchema::authored_member` with it.
`CardSchema::cell(name)` resolves a document key to a field or a variant cell,
`CardSchema::variant_owner(name)` names the enum declaring one,
`FieldSchema::variant_cells()` is the union of a field's worlds and
`FieldSchema::live_cells(value)` the world a value selects. `TypedWriter::set`
and `TypedReader::get` take a cell's name directly.

### `usaf_memo`

The fixture plate reads `data.classification` and the four `cui_*` package
arguments from `data.controlled_by`, `data.category`,
`data.limited_dissemination` and `data.poc`. `Quill.yaml` is unchanged, and
`usaf_memo` keeps its declared `version: 0.2.0`, so a stored document's `$quill`
selector does not report the move; audit by content.

## The `loss` key leaves an island

An island's canonical form is `{id, type, props}`.

### Why the class goes rather than grows

One import minted a class other than `lossless`: a table cell holding an inline
image, whose alt text lands as the cell's text and whose url lands nowhere.
That is a fact about the import, not about the island it mints. A cell written
`| a cat |` and a cell written `| ![a cat](cat.png) |` mint the same `props`,
and the markdown projection has no syntax to tell them apart on the way back
out — so the class survived neither a `to_markdown` → `from_markdown` hop nor
re-derivation from the row that carried it, and the content fixed point had to
be stated modulo it.

Nothing in the engine read it either: export dispatches on an island's `type`,
the Typst emitter and the acroform binder never looked, and an `islandOps` `set`
stored whatever class the op named. What is left is a per-island annotation that
the content model guarded as an invariant it could not check. The guard goes with
it: the closed vocabularies now cover the four discriminators a projection
dispatches on (line `kind`, container, mark `type`, island `type`), and a row is
no longer refused over a field no reader consumed.

A host that surfaced the annotation to a user surfaces the drop at the import
instead, where the markdown it is about is still in hand. A row read later cannot
say what its markdown once held.

## The `island` line kind retires

A line whose sole content is an island's slot carried one of two kinds. A
`table`'s line was `{"kind":"island"}`, an `image`'s was `{"kind":"para"}`, and
which one a document held was never the line's to decide: markdown writes a
table as a block and an image inline, so `IslandType::block_only` already
settled it and `Content::normalize` already wrote the answer. The kind was a
second copy of a fact the island beside it carried.

Now there is one copy. Every line holding a lone slot is a `para`:

```json
{ "kind": "para", "containers": [] }
```

Whether that slot's markup is a block is read off the island — the same place
the mint, the placement refusal (`BlockIslandNotAlone`) and both emitters were
already reading it.

### Branching on `line.kind === 'island'`

The TypeScript union `ContentLineKind` no longer carries the arm, so
`npm run typecheck` reports the comparison rather than leaving it to run time. A
host that built an editor node from the kind reads the island instead. The slot
index is the number of slots in the text before the line:

```js
const SLOT = '￼'

function blockIslandAt(body, i) {
  const segs = body.text.split('\n')
  if (segs[i] !== SLOT) return null
  const before = segs.slice(0, i).join('\n').split(SLOT).length - 1
  const island = body.islands[before]
  return island?.type === 'table' ? island : null
}
```

`type === 'table'` is the whole of `block_only` today. A host that would rather
not track which types are block markup can read the projection instead:
`exportMarkdown` still writes the table as its own block.

### `{ op: 'setKind', kind: 'island' }` is no longer a spelling

Landing a block island was three channels — the delta opening the line, the
island op filling it, a `setKind` tagging it. It is two now, and the `setKind`
goes:

```js
// 0.114
doc.applyChange({}, {
  delta: { ops: [{ retain: 5 }, { insert: '\n' }] },
  islandOps: [{ op: 'insert', at: 6, id: 'isl-t', type: 'table', props }],
  lineOps: [{ op: 'setKind', line: 1, kind: 'island' }],
})
// 0.115
doc.applyChange({}, {
  delta: { ops: [{ retain: 5 }, { insert: '\n' }] },
  islandOps: [{ op: 'insert', at: 6, id: 'isl-t', type: 'table', props }],
})
```

The op wire is forgiving rather than strict here, unlike the `attrs` respelling
of 0.112: a `setKind` still naming `island` lands as `para`, which is where it
would have settled anyway. It is a type error, not a run-time one.

### Rust: `LineKind::Island` is gone

An exhaustive `match` over `LineKind` stops compiling, and
`LineKind::takes_continuations` is now necessary but not sufficient for "this
block is one line" — a `para` holding a block island's slot is one line too.
`Content::block_island_at(line)` is the read that answers it — the island
backing that line's lone slot, where its markup is a block — and
`Content::normalize` reads the same fact where it used to read the kind.

## What moves without breaking

**Canonical bytes**, for any document holding an island (the `loss` key) and for
every document holding a table (the line kind), so **content hashes change**:
cache keys and template-divergence checks keyed on stored bytes recompute once,
on the rows that carry one.

**The storage tag** is now `quillmark/document@0.115.0`
(`Document.currentStorageVersion`). Rows tagged `@0.112.0`, `@0.93.0`, `@0.92.0`,
`@0.82.0` and `@0.81.0` migrate forward on read; nothing else about the envelope
changed, and the `@0.112.0` hop is the `body` decode and nothing more.

**Nothing else.** Exported markdown, generated Typst, rendered output and every
island's own props are unchanged: neither the class nor the kind was what an
emitter dispatched an island on.

## Why the decoder, not a migration

A migration can only reach the card `body`. Every *other* stored content sits
inside an opaque payload value with no schema tag over it — a `richtext` field
(where most stored content lives), a `plaintext` field, an `array<richtext>`
element, a content property on an `object` field, a `$seed` overlay, and `$ext`,
which is arbitrary host data by contract. A walk that rewrote something in `$ext`
that merely *looked* like content would be corrupting a consumer's payload, so
there is no walk that finds all the stored content and nothing else.

Had the decoder been made `para`-only, every table in one of those values would
have failed to open: an unknown line kind is `ParseError::UnknownName`, which
refuses the row rather than dropping the line.

So the read is in the decoder, it is one arm — `"island" | "para" =>
LineKind::Para` — and it is permanent. A legacy DTO retires when no row carries
its tag; these values carry no tag, so "no rows remain in that shape" is not
checkable. Read-repair converges the population — a row read and written back
rests in the current spelling — and cold rows keep the arm alive. The ignored
`loss` key rests on the same reasoning.

## Checklist

- Flatten every document that nests a variant world under its enum; `validate`
  finds them as `validation::type_mismatch` on the enum.
- Read `data.<enum>` and `data.<cell>` in plates; drop the `.value` step and any
  guard on a dormant world's key.
- Match region and diagnostic addresses on the cell's bare name; `doc.pathFor`
  mints the prefix.
- Rename a variant cell that shares a name with a card field or another enum's
  cell.
- Drop `VARIANT_DISCRIMINANT_KEY` and `authored_member` reads; use
  `CardSchema::cell` and `FieldSchema::live_cells`.
- Drop `loss` from every island literal and from anything that read it.
- Replace every seam read of `line.kind === 'island'` with a read of the island
  backing the line's slot. `npm run typecheck` finds these.
- Drop the `setKind` from every block-island bundle. The type checker finds
  these too; they would have landed as `para` regardless.
- Fix Rust `match`es over `LineKind` and destructures of `Island`, and any
  predicate that read `takes_continuations` as "this block is one line".
- Recompute anything keyed on a content hash or on stored document bytes, for
  documents holding an island or a table.
- Leave your stored documents alone.
