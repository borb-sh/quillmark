# 0.134 → 0.135 — a whole-document write under a read base merges by structure and reports what both sides changed

## `reviseDocument` under `baseMarkdown` writes what it can

The break no type checker reports: **a whole-document write under a markdown base no longer throws where both sides changed one place.** In 0.134 the writer's edit and the change since merged as one run of lines, and two edits to one line, or to touching lines, threw `edit::rebase_conflict` and wrote nothing. Now the two merge card by card and field by field, and the write lands every change only one side made. A place both changed keeps its value now and is named in the receipt's `conflicts`, so a host that relied on the throw to keep a stale write out writes part of it instead.

```javascript
// 0.134
try {
  writer.reviseDocument(reply, { baseMarkdown: read })
} catch (e) {
  if (e.diagnostics[0].code === 'edit::rebase_conflict') retry()
}

// 0.135
const { conflicts } = writer.reviseDocument(reply, { baseMarkdown: read })
for (const { path, current, proposed } of conflicts) offer(path, current, proposed)
```

| Break | Surface | Action |
|---|---|---|
| `revise_document_against(Base::Read(..), ..)` lands a partial merge where it refused with `BaseError::Conflict` | Rust, WASM, Python | Read `DocumentRevised::conflicts` (`conflicts` in JS and Python); each entry is `{path, base, current, proposed}`, the value now kept |
| `edit::rebase_conflict` on a whole document means no merge can stand: a side reordered the cards, or both changed a card's `$quill`, `$seed` or `$ext` apart | Rust, WASM, Python | A host still routes the code to a fresh read |
| `DocumentRevised` gains `conflicts` | Rust, WASM, Python | A Rust struct literal cannot build it (`#[non_exhaustive]`); nothing to change elsewhere |

Two edits to different rows of one array, or different keys of one object, both land where a line merge refused them as touching. `reviseBody` and `reviseField` under `baseMarkdown` are unchanged: they merge by line and throw where lines clash.

New, with nothing to migrate: `MergeConflict` in Rust and TypeScript, and the `MergeConflict` `TypedDict` in Python.

## A step holding a key it does not define is refused

A change step decodes only the keys its kind defines. In 0.134 an unknown key was ignored, so a misspelled `delete` turned a guarded replace into a pure insert and a misspelled `quote` dropped the guard. Now the change is refused at the decoder and nothing is written: `ParseError::UnknownKey { at, key }` in Rust, a thrown `Error` naming the key in JS, a `ValueError` naming it in Python.

```javascript
// 0.134: lands as an insert of "hi" before "hello"
// 0.135: throws, naming `delet`
doc.apply({}, { steps: [{ splice: { at: 0, delet: 'hello', insert: 'hi' } }] })
```

| Break | Surface | Action |
|---|---|---|
| A step object holding a key its kind does not define is refused | Rust, WASM, Python | Spell each step's keys as CONTENT.md § Changes lists them; the `attrs` and `props` bags stay open |
| `quillmark_content::wire::ParseError` gains `UnknownKey` | Rust | A match over it adds the arm |

## A stale write holds each id to the part it read

A rebase judges a block, container or island by incarnation, not by its spelling. In 0.134 a stale `apply`, `revise` or `replace` whose step named an id the writes since had removed and minted again, as an editor does that deletes a block and presses Enter, landed on the new block. Now the step refuses with `edit::rebase_conflict`, reason `missing`, and nothing is written. So does a stale step naming a block a write since moved, since a move removes the block and inserts it again under its id.

A revise or replace mints from the value its base names and the value it lands on, never the card's log of recent writes, so one write over equal values stores equal bytes on every card. A stale write whose new part takes an id a write since also introduced lands under a renamed id, which the receipt's `applied` names.

| Break | Surface | Action |
|---|---|---|
| A stale step naming an id a write since removed refuses as `missing`, though the id is held again | Rust, WASM, Python | A host routes `edit::rebase_conflict` to a fresh read, as for any conflict |
| A revise or replace no longer mints past ids only the card's log held | Rust, WASM, Python | Nothing to change; a card with history stores what a fresh one does |
| A rebased write renames an id it introduces that a write since also introduced | Rust, WASM, Python | Read the ids the write landed from the receipt's `applied` or the value, not from the change sent |

## A content `revise` keeps what its read does not spell, or refuses

`doc.revise(addr, markdown)` (Rust `Card::revise`, Python `doc.revise`) no longer diffs the writer's markdown against the value cold. It rebases the writer's edit over what the annotated read does not spell: an empty paragraph, a lone or trailing hard break, a cell's break before a paragraph break, a table's rows past the import's budget. In 0.134 a revise with the unchanged read deleted them and reported nothing; now they stay. Formatting inside a link's text, which 0.134's export dropped and every revise with it, is now written inside the link's brackets, so it needs no rebase; `to_markdown_checked` also names an `x-` block or mark among its losses (`Loss::ExtBlock`, `Loss::ExtMark`) where it reported none. A revise that rewrites what the read re-spelled throws `edit::rebase_conflict`, with no base passed, where 0.134 wrote it and dropped the rest.

| Break | Surface | Action |
|---|---|---|
| `revise` can throw `edit::rebase_conflict` without a `base` | Rust, WASM, Python | Route the code as for a stale base: read again, show the writer the read, and retry |
| `diff::revise` answers `ReviseError` (`Import` or `Conflict`) where it answered `ImportError` | Rust | Match `ReviseError::Import` where you matched the import error |

## Anchor text is spelled as stored

`anchorContexts`, `anchorContext`, and a content write's `droppedAnchors` spell a quote, prefix and suffix as the value stores them: a hard break is `U+2028` and a cell's block break is one `\n`, as `movedAnchors.before` already did. In 0.134 they spelled a hard break as `\n` and a cell's block break as `\n\n`, so one receipt spelled an anchor two ways. `reattach` places a selector in either spelling for this release: one stored under 0.134 still finds its text.

| Break | Surface | Action |
|---|---|---|
| A selector's `quote`, `prefix`, `suffix` hold `U+2028` for a hard break | Rust, WASM, Python | Compare selectors through `reattach`, or normalize both spellings before comparing them yourself |

## Content values, changes and markdown are bounded

**A value, change or markdown input past a bound now refuses where it was read in full.** No document a person writes nears these; a host that generates content should check it stays inside them.

| Bound | Value | Refused as | Where |
|---|---|---|---|
| Marks on one text, a field's or a slot's | 64 + 4 per character, each mark counted once per block and line it spans before it is cut at each | `Invariant::TooManyMarks`, `edit::too_many_marks` | decoding a value (`fromStored`, a field read, `replace`, `diff`, `invert`); a change, at the step that would pass it; `repair` keeps those in order up to it |
| Anchors on a value | 100 000 | `Invariant::TooManyAnchors`, `edit::too_many_anchors` | decoding; a change; `repair` keeps those in reading order up to it |
| Markdown one import reads | 10 MiB (`MAX_MARKDOWN_SIZE`) | `ImportError::TooLarge`, `edit::input_too_large` | `revise`, `reviseBody`, `reviseField`, `importMarkdown` and every other import, as a parse already was |
| A content value's text and its slots' texts, at a binding | 10 MiB | `edit::input_too_large` | every WASM and Python door taking a `Content` or `RawContent` |
| Steps in one change, nested ones counted | 16 384 (`MAX_CHANGE_STEPS`) | `edit::too_many_steps` | `apply` in every binding and `Card::write`, and every WASM and Python door taking a `Change` |
| Characters footnote notes copy past each note's first reference | 1 000 000 (`MAX_NOTE_COPIES`) | a reference past it stays as its `[^label]` text, warning `footnote:size` | every markdown import |

Before, a few kilobytes of `x-` marks of distinct attributes over many blocks decoded into gigabytes, and a note cited thousands of times into tens of megabytes; on wasm32 either trapped. A Python `Content` past a bound raises the diagnostics error under these codes, where an invalid value raises `ValueError`.

| Break | Surface | Action |
|---|---|---|
| `Invariant` gains `TooManyMarks` and `TooManyAnchors`; `ImportError` gains `TooLarge`; `Dropped` gains `FootnoteSize`; `EditError` gains `InputTooLarge`, `TooManySteps`, `TooManyMarks` and `TooManyAnchors` | Rust | An exhaustive `match` adds the arms |
| A change refused for its marks or anchors throws `edit::too_many_marks` / `edit::too_many_anchors` where it threw `edit::content_apply` | Rust, WASM, Python | Route the new codes |

New, with nothing to migrate: `MAX_MARKDOWN_SIZE`, `MAX_NOTE_COPIES`, `MARKS_PER_CHAR`, `MARKS_BASE`, `max_marks`, `MAX_ANCHORS` and `Content::check_bounds` in `quillmark-content`; `MAX_CHANGE_STEPS`, `check_change` and `check_content_value` in `quillmark_core::document`.

## A live client mints through the engine, under its actor

The break no type checker reports: **an id may no longer open with `?`.** A record a change puts may carry a placeholder, `?` and an id, which the write that lands the change fills with an id it mints and names in the receipt's new `minted`; a value holding an id that opens with `?` is no longer valid. A write takes an `actor` beside its `base`, and every id it mints is then `{actor}:{prefix}{n}`, so two clients writing from one value never mint one id. Without an actor a write mints `{prefix}{n}` as before.

```javascript
// 0.134: the client minted, and could collide with another client's mint
doc.apply(addr, { steps: [{ splice: { at, insert: '\n', blocks: [{ id: myMint(), kind: 'para' }] } }] }, { base })

// 0.135
const { minted } = doc.apply(addr, { steps: [{ splice: { at, insert: '\n', blocks: [{ id: '?new', kind: 'para' }] } }] }, { base, actor: session.id })
minted['?new'] // 'ann:b0'
```

| Break | Surface | Action |
|---|---|---|
| An id opening with `?` is invalid: a value holding one refuses, and a change putting one is a placeholder the write fills | Rust, WASM, Python | Rename any stored id that opens with `?` before upgrading |
| `gestures::split_block` takes `Option<&str>`; `indent`, `outdent`, `wrap` and an id-less `split_block` put placeholders (`?0`, `?1`, …) that `apply` fills | Rust | Pass `Some(id)` for a chosen id, and read the ids from `Applied::minted` |
| `Card::apply`, `revise`, `replace`, `write` and `write_in` take `impl Into<WriteOptions>` where they took `Option<&str>` | Rust | A `None` or `Some(hash.as_str())` still compiles; pass `WriteOptions { base, actor }` for an actor; an `Option<&String>` needs `.map(String::as_str)` |
| `Edit` gains `Gesture`; `Receipt` and `Applied` gain `minted`; `EditError` gains `InvalidActor` (`edit::invalid_actor`) | Rust | An exhaustive `match` adds the arms; a struct literal adds the field |

New, with nothing to migrate: `WriteOptions.actor` and `Receipt.minted` in every binding (`actor=` and `"minted"` in Python), `ids::is_placeholder`, `ids::is_actor` and the `mint` module in `quillmark-content`.

## Gestures are document verbs, and a range lowers exactly

The WASM gesture functions that answered a `Change` over a whole `Content` are gone; the gestures are `Document` verbs that write and answer a `Receipt`, as `apply` does, rebasing over a stale `base` and minting under `actor`. `diffRange(before, after, { from, to })` lowers the range ProseMirror's `ReplaceStep` names as one exact splice, so typing a letter into a word is a one-letter splice rather than a rewrite of the word; `doc.locate(addr, offset)` answers the block at an offset.

```javascript
// 0.134
doc.apply(addr, splitBlock(doc.read(addr), at, 'b9'), { base })

// 0.135
const { minted } = doc.splitBlock(addr, at, { base, actor })
```

| Break | Surface | Action |
|---|---|---|
| `splitBlock`, `joinBlocks`, `deleteRange`, `indent`, `outdent` and `wrap` are no longer module functions | WASM | Call `doc.splitBlock(addr, at, opts)`, `doc.joinBlocks(addr, id, opts)`, `doc.deleteRange(addr, start, end, opts)`, `doc.indent(addr, first, last, opts)`, `doc.outdent(addr, first, last, opts)` or `doc.wrap(addr, first, last, kind, opts)`; `splitBlock` takes the new id as `opts.id` |

New, with nothing to migrate: `diffRange` and `doc.locate` in WASM; `diff::diff_range`, `Card::locate` and the `Card` gesture verbs in Rust.

## A `text` field rests as a content object spelling `codec: "plain"`

The break no type checker reports: **`getStored` on a conformed `text` field answers a content object, not a string.** A `text` field rests as `Content` like a `richtext` one, its `codec: "plain"` key marking the literal codec, so it holds comment anchors and ids, and `toMarkdown` still writes it as its literal text. A host that read `getStored` as the string reads it with `reader.get` (the literal text) or `reader.getContent`.

```javascript
// 0.134
const title = doc.getStored({ field: 'title' })          // "a *literal* line"

// 0.135
doc.getStored({ field: 'title' })   // { text: "a *literal* line", blocks: [...], codec: "plain" }
quill.reader(doc).get('title')      // "a *literal* line"
```

| Break | Surface | Action |
|---|---|---|
| A conformed `text` field's stored value is a `Content` spelling `codec: "plain"` | Rust, WASM, Python | Read it through `reader.get` or `reader.getContent`; a stored string still reads, and rewrites to the object at its next bound load |
| `field_hash` of a `text` field hashes its content, ids and anchors included, not its literal text | Rust, WASM, Python | A hash read before the upgrade is stale once the field conforms; read it again |
| `Content` gains `codec`; `Invariant::NotPlain` refuses a plain value holding a mark, an island, a container or a block other than a paragraph | Rust, WASM, Python | A Rust struct literal of `Content` or `Raw` names `codec` (`Codec::Rich` for what it built before) |
| The render plate's `text` value carries `codec: "plain"`, and a `text` blank is the empty plain content | Rust, WASM, Python | A plate reads it through `qm.str` or as content, unchanged |

A stored row needs no migration: a `text` field holding a string is the authored form, and the bound door conforms it once. `reattach` answers a whole-field selector, an empty `quote`, `prefix` and `suffix` at a path naming a value that holds no content, as reattached, so a comment can sit on an enum, a number, a date or a boolean ([COMMENTS.md](https://github.com/borb-sh/quillmark/blob/main/prose/canon/COMMENTS.md) § "Text and scalar fields").
