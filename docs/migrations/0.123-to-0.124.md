# 0.123 → 0.124 — surface parity: one stored model, every surface a codec of it

A document's stored JSON is its one model, and markdown, the op wire and the
Typst lowering are codecs or projections of it;
[PARITY.md](https://github.com/borb-sh/quillmark/blob/main/prose/canon/PARITY.md)
holds what each surface does with each construct. Each section below is one
concern, those whose breaks no type checker reports first, and the table
closing the guide lists every break.

## An HTML block's markdown imports

**Markdown inside a type 6 or 7 HTML block renders, where it was dropped.**
CommonMark runs a block that opens with a tag line, such as `<div>`,
`<center>`, `<details>`, `<p>` or a custom element, to the next blank line, and
0.123 dropped the whole block with the markdown in it. Each line holding only
tags now drops, and every other line imports as markdown, whether or not blank
lines surround the tags.

```markdown
<div align="center">
| Item | Qty |
|---|---|
| Taro | 3 |
</div>
```

0.123 rendered nothing for this; 0.124 renders the table, without the
centering. With a blank line under the `<div>`, the usual GitHub spelling, the
table rendered before and still does. A `<center>` around a signature block
renders the signature, and the text an embedded `<svg>` holds renders as text.
A `<pre>`, `<script>`, `<style>` or `<textarea>` block still drops whole, as
does a comment. Text after such a block's closing tag, on that tag's line,
renders as a paragraph of its own, where 0.123 dropped it with the block.

Nothing reports the change: the `parse::dropped_construct` an opening tag
raises fires whether or not a blank line follows it. To find one, search
markdown bodies and `richtext` values for a line opening with `<` with no blank
line below it. Delete what should not render, or put it in a comment.

**A line holding only tags drops wherever it stands, and under a paragraph's
text it ends the paragraph.** 0.123 read such a line under text as inline HTML,
so the paragraph ran on through it, `<u>` alone on its line opened an
underline, and `<br>` alone on its line was a line break. 0.124 renders the
text above and below it as two paragraphs, with no underline and no break. The
allowlist is inline: `<u>…</u>` inside a line is underline and a `<br>` inside
a line a break, as before. Write `<u>` and `</u>` inside the line they
underline, and `<br>` at the end of the line it breaks.

**A tag line between list items leaves one list, as a blank line there
would.**

```markdown
1. First
</div>

1. Second
```

0.123 ended the list at the tag and numbered `Second` 1; 0.124 numbers it 2.

**A type 7 tag on the line after a table's rows ends the table, where it added
an empty row.** `</quill-table>` under the rows rendered an empty last row;
`</div>` and `</center>` ended the table already.

**A fenced code block holding `<!-- a --> b` keeps its line, where 0.123 broke
it after `-->`.** The comment repair edited the raw text, fences included, and
now edits only HTML the parser found. Outside a fence, text after a comment's
`-->` on the same line is a paragraph of its own, where 0.123 joined the next
line to it.

## A footnote-shaped definition and its references are the text written

CommonMark reads `[^1]: Word` as a link reference definition, so 0.123 dropped
the line and rendered `text[^1]` as `text^1` linked to `Word`. 0.124 renders
the line as `[^1]: Word` and the reference as `[^1]`, which is no link, and the
body holding the definition warns `parse::dropped_construct` with the
construct `footnote_definition`. Quillmark has no footnotes: write the note
inline, or as a list under the text.

## Text after a block nested in a tight list item opens its own line

````markdown
- item
  ```
  code
  ```
  after
````

0.123 joined such text to the nested block's last line, so `after` imported
into the code block; 0.124 renders it as a paragraph in the item. The same
holds after a nested quote, heading, rule, table or HTML block.

## Stored rows

A stored row's bytes do not move: its content does not re-import on load. A
row tagged `quillmark/document@0.92.0`, whose bodies are markdown, imports them
on load as 0.124 imports any markdown.

## A markdown import reports what it drops

The warning is `parse::dropped_construct`, `Severity::Warning`, one per
construct per body or field: `args.construct` is a raw tag's lowercase name
(`div`, `span`, `pre`, `quill-keep`) or `footnote_definition`, and `args.count`
how many. A closing tag, a comment, an inline `<u>` or `<br>`, and
`quill-anchor` report nothing. A parse anchors each at the body it sat in
(`main.body`, `cards.<kind>[<i>].body`) on `Parsed.warnings`, which is
`doc.warnings` in both bindings, so it reaches `RenderResult.warnings` and the
warnings the CLI prints. A host that fails on any warning, or counts them,
meets a new entry for every document holding a raw tag outside the allowlist.
`quillmark validate` fails a quill whose `example.md` body holds a raw tag or a
footnote-shaped definition, as `cli::example_not_clean`; drop the markup from
the example.

## An import and a revise return their warnings

**`quillmark_content::import::from_markdown` returns
`Imported { content, warnings }`.** `.content` is 0.123's `Normalized`, and
`warnings` a `Vec<ImportWarning>` holding one
`ImportWarning::DroppedConstruct { construct, count }` per construct.
`quillmark_content::delta::diff_import` returns
`(Normalized, Delta, Vec<ImportWarning>)`.
`quillmark_core::document::dropped_construct` turns one into the diagnostic.

**A revise returns a `Revised { delta, warnings }` receipt, where it returned
the `Delta`.** `Card::revise_body`, `revise_field` and `revise_field_checked`,
their `CardMut` twins, and the typed `TypedWriter::revise_body` /
`revise_field` and `CardWriter::revise_body` / `revise_field` return
`Result<Revised, EditError>`, `#[must_use]`. A `Card` verb does not know its
card's address, so its warnings carry no `path`; the typed writer anchors them
at the body or field, and `Revised::with_path` does for any caller that knows
the address. `TypedWriter::add_card` returns the body's warnings,
`Result<Vec<Diagnostic>, _>`, where it returned `()`. `quillmark::Revised`
re-exports the receipt.

```rust
let delta = card.revise_body(md)?;        // 0.123
let delta = card.revise_body(md)?.delta;  // 0.124; .warnings holds what the import dropped
```

**In WASM, `importMarkdown`, `rebase` and every revise return the warnings
beside the value.** `importMarkdown(md)` returns `{ content, warnings }`
(`Imported`), where it returned the `Content`, so the cold write takes
`.content`. `rebase(base, md)` returns `{ content, delta, warnings }`.
`doc.revise(addr, md)`, `writer.reviseBody`, `writer.reviseField` and their
`writer.card(i)` twins return `{ delta, warnings }` (`Revised`), where they
returned the `Delta`, with each warning's `path` the address written.
`writer.addCard` returns the body's warnings, where it returned `undefined`.
The warnings of `importMarkdown` and `rebase` carry no `path`: there is no
document.

```js
doc.overwrite(addr, importMarkdown(md));          // 0.123; 0.124 throws, the argument being no Content
doc.overwrite(addr, importMarkdown(md).content);  // 0.124
const delta = doc.revise(addr, md);               // 0.123
const { delta, warnings } = doc.revise(addr, md); // 0.124
```

**In Python, `Writer.revise_body`, `revise_field` and `add_card` return the
import's warnings as `list[Diagnostic]`, where they returned `None`.** Each
anchors at the body or field written. The `Delta` stays behind, as before.
