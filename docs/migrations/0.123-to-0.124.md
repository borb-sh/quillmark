# 0.123 → 0.124 — surface parity: one stored model, every surface a codec of it

A document's stored JSON is its one model, and markdown, the op wire and the
Typst lowering are codecs or projections of it;
[PARITY.md](https://github.com/borb-sh/quillmark/blob/main/prose/canon/PARITY.md)
holds what each surface does with each construct. Each section below is one
concern, those whose breaks no type checker reports first, and the table
closing the guide lists every break.

## Raw HTML around markdown

**HTML other than the carrier still drops as CommonMark reads it, and the
import now says so.** CommonMark runs a block that opens with a tag line, such
as `<div>`, `<center>`, `<details>`, `<p>` or a custom element, to the next
blank line, and the block drops with the markdown it holds, as in 0.123:

```markdown
<div align="center">
| Item | Qty |
|---|---|
| Taro | 3 |
</div>
```

renders nothing, and warns `parse::dropped_construct` (`div`). With a blank
line under the `<div>` and above the `</div>`, the usual GitHub spelling, the
table renders. A block holding only closing tags and the text it drops warns
under its first tag. Put blank lines around the tags, or delete them. A
`quill-*` tag reads the same way: `<quill-keep>` tight above a table drops the
table with it and warns `quill-keep`.

**An inline `<u>` pairs as HTML pairs it.** A `</u>` closes the innermost
`<u>` still open, one carrying an attribute included, and never a `**`:
`**bold <u class="x">a</u> b**` renders all three words bold, where 0.123 ended
the bold at `</u>`, and `<u>a **b</u> c**` underlines `a b` and bolds `b c`. A
`<u>` still open where its paragraph, heading, item text or table cell ends
drops and reports as `u`, where 0.123 underlined the rest of the body; a
hundred of them no longer fail the import. Close each `<u>` in the text it
opens in. Export writes a `<u>` tag outside the `**`, `_` and `~~` delimiters
at its position, so `**ab<u>cd</u>**` exports as `**ab<u>cd**</u>`: both read
back as the same content.

**A line holding only tags on the line after a table's rows ends the table,
where a type 7 tag added an empty row.** `</quill-table>` under the rows
rendered an empty last row; `</div>` and `</center>` ended the table already.

**A fenced code block holding `<!-- a --> b` keeps its line, where 0.123 broke
it after `-->`.** The comment repair edited the raw text, fences included, and
now edits only HTML the parser found.

## A footnote-shaped definition warns

CommonMark reads `[^1]: Word` as a link reference definition, so the line
drops and `text[^1]` renders as `text^1` linked to `Word`, as in 0.123. 0.124
also warns `parse::dropped_construct` with the construct
`footnote_definition`. Quillmark has no footnotes: write the note inline, or
as a list under the text.

## Text after a block nested in a tight list item opens its own line

````markdown
- item
  ```
  code
  ```
  after
````

0.123 joined such text to the nested block's last line, so `after` imported
into the code block; 0.124 renders it as a paragraph in the item. The same
holds after a nested quote, heading, rule, table or HTML block.

## Stored rows

**The storage tag is `quillmark/document@0.124.0`**, the first that can hold an
element. A row under an older tag loads as before, and its content does not
re-import. A save rewrites it under the new tag, so a hash over stored bytes
recomputes once, though nothing else in the row moves. A 0.123 build refuses a
row from then on, as a build too old for its tag. A row tagged
`quillmark/document@0.92.0`, whose bodies are markdown, imports them on load as
0.124 imports any markdown.

## A markdown import reports what it drops

The warning is `parse::dropped_construct`, `Severity::Warning`, one per
construct per body or field: `args.construct` is a raw tag's lowercase name
(`div`, `span`, `pre`) or `footnote_definition`, and `args.count` how many. A
closing tag, a comment, an inline `<u>` or `<br>`, `quill-anchor` and a
`quill-*` element that closes report nothing; one left unclosed, inside a
line, or tight against markdown reports as `quill-<name>`. A `<quill-table>`
wrapper around one table folds its attributes into the table and reports
nothing; one wrapping anything else reports as `quill-table`, and an attribute
it cannot fold as `quill-table[<attr>]`. A `<quill-cell>` tag reports as
`quill-cell`. A parse anchors each at the body it sat in (`main.body`,
`cards.<kind>[<i>].body`) on `Parsed.warnings`, which is `doc.warnings` in both
bindings, and the CLI prints it. A host that
fails on any warning, or counts them, meets a new entry for every document
holding a raw tag outside the allowlist.
`quillmark validate` fails a quill whose `example.md` body holds a raw tag or a
footnote-shaped definition, as `cli::example_not_clean`; drop the markup from
the example.

## A one-shot render carries the render's warnings alone

0.123's WASM `engine.render(quill, doc)` and Python `Quillmark.render` put
`doc.warnings`, the load's parse and `conform::*` warnings, ahead of
`RenderResult.warnings`. They no longer do: a render carries every
`quill.validate(doc)` warning, then the compile's, as a session's render and
core's `Quillmark::render` do. `doc.warnings` reports the load, and a revise or
a store can change what the document holds after it, so a render after a
revise kept reporting a tag the revise had removed and never the ones it
dropped. A host that showed the load's warnings through the render reads
`doc.warnings` after the load, and a revise's `warnings` after each revise.
The CLI's `render` parses and renders in one command, and still prints its
parse's warnings first.

## An import and a revise return their warnings

**`quillmark_content::import::from_markdown` returns
`Imported { content, warnings }`.** `.content` is 0.123's `Normalized`, and
`warnings` a `Vec<ImportWarning>` holding one
`ImportWarning::DroppedConstruct { construct, count }` per construct.
`quillmark_content::delta::diff_import` returns
`(Normalized, Delta, Vec<ImportWarning>)`.
`quillmark_core::document::dropped_construct` turns one into the diagnostic.

**A revise returns a `Revised { delta, warnings }` receipt, where it returned
the `Delta`.** `Card::revise_body`, `revise_field` and `revise_field_checked`,
their `CardMut` twins, and the typed `TypedWriter::revise_body` /
`revise_field` and `CardWriter::revise_body` / `revise_field` return
`Result<Revised, EditError>`, `#[must_use]`. A `Card` verb does not know its
card's address, so its warnings carry no `path`; the typed writer anchors them
at the body or field, and `Revised::with_path` does for any caller that knows
the address. `TypedWriter::add_card` returns the body's warnings,
`Result<Vec<Diagnostic>, _>`, where it returned `()`. `quillmark::Revised`
re-exports the receipt.

```rust
let delta = card.revise_body(md)?;        // 0.123
let delta = card.revise_body(md)?.delta;  // 0.124; .warnings holds what the import dropped
```

**In WASM, `importMarkdown`, `rebase` and every revise return the warnings
beside the value.** `importMarkdown(md)` returns `{ content, warnings }`
(`Imported`), where it returned the `Content`, so the cold write takes
`.content`. `rebase(base, md)` returns `{ content, delta, warnings }`.
`doc.revise(addr, md)`, `writer.reviseBody`, `writer.reviseField` and their
`writer.card(i)` twins return `{ delta, warnings }` (`Revised`), where they
returned the `Delta`, with each warning's `path` the address written.
`writer.addCard` returns the body's warnings, where it returned `undefined`.
The warnings of `importMarkdown` and `rebase` carry no `path`: there is no
document.

```js
doc.overwrite(addr, importMarkdown(md));          // 0.123; 0.124 throws, the argument being no Content
doc.overwrite(addr, importMarkdown(md).content);  // 0.124
const delta = doc.revise(addr, md);               // 0.123
const { delta, warnings } = doc.revise(addr, md); // 0.124
```

**In Python, `Writer.revise_body`, `revise_field` and `add_card` return the
import's warnings as `list[Diagnostic]`, where they returned `None`.** Each
anchors at the body or field written. The `Delta` stays behind, as before.

## `validate` reports what the backend will not draw

**`Quill::validate` warns `validation::declined_construct` at a content field
holding a construct the quill's backend draws nothing for.** One per field and
construct, `Severity::Warning`, with `args.construct` and `args.count` and the
field's `path`: `main.body`, `main.<field>`, `cards.<kind>[<i>].body`. The
Typst backend declines `image`, so a markdown image in a body or `richtext`
field now warns at `validate`, where only the render reported it, and so
does a `richtext` default the document leaves unset. The
`construct` values are those `backend::declined_construct` carries. WASM and
Python `quill.validate(doc)` return it, `quillmark check` prints it and exits
`1` on it under `--strict`, and `quillmark validate` fails a quill whose
`example.md` holds an image, as `cli::example_not_clean`. A host that gates on
any `validate` diagnostic meets it; route on the code. A one-shot render's
`RenderResult.warnings` leaves it out and carries the backend's
`backend::declined_construct`, as before.

**The acroform backend declines every construct but the paragraph.** A
heading, rule, code block, list, quote, table or image in an acroform quill's
content warns `validation::declined_construct` at `validate` and
`backend::declined_construct` on the session's warnings and
`RenderResult.warnings`, where an acroform render warned nothing. The field
still binds its plaintext, as before.

## A `quill-table` wrapper lays out its table

**A Typst quill lays out the `quill-table` attributes `widths` and `align`,
where 0.123 dropped the tags.**

```markdown
<quill-table align="center" widths="2 1">

| Item | Amount |
| --- | --- |
| Total | 42 |

</quill-table>
```

0.123 rendered this table auto-fit, at the plate's placement; 0.124 weights
the columns and centers the table. A `<quill-keep>` around the wrapper keeps
the table on one page. A document whose markdown already holds such tags
renders the layout they spell. The acroform backend typesets no table and
declines it as before.

## A `quill-*` element is stored, and renders through the plate

**A `quill-<name>` element is content, where 0.123 dropped its tags.** A pair
of tag lines, each set apart by blank lines, wraps the blocks between them and
keeps its attributes as strings.

```markdown
<quill-keep>

**Signed**
J. Doe

</quill-keep>
```

0.123 dropped each tag and rendered what the pair wraps; 0.124 stores the
element. One still open where its list item, quote or body ends, a
self-closing tag and a tag inside a line drop, warning
`parse::dropped_construct` as `quill-<name>`, what they wrap importing; a tag
line tight against markdown drops with the markdown its block holds, warning
the same. An attribute outside the carrier grammar drops alone, warning
`quill-<name>[<attr>]`. `quill-table` and `quill-anchor` keep their meaning,
and `quill-cell` is reserved.

**A Typst quill renders an element through the renderer its plate registers
under the element's name, and draws what any other wraps.** The renderer lives
in the helper's `elements` state and takes the element's attributes, each the
string written, its content, and `inline`, which is `false` for every element
0.124 stores:

```typst
#import "@local/quillmark-helper:0.1.0": data, elements
#elements.update(e => e + (boxed: (attrs, body, inline: false) => block(stroke: 0.5pt, inset: 6pt, body)))
```

The dispatcher reads the registry's final value, so the update may stand
anywhere in the plate, after the content it renders included.

**An element around nothing is its two tag lines.** `<quill-sig>` on the line
above `</quill-sig>` is an element holding an empty paragraph, and export
writes it so; a body holding only that is not blank, and its plate's renderer
draws it.
`<quill-sig/>` drops, warning `quill-sig`, since HTML reads a self-closing
custom element as an open tag.

The built-in `keep` holds its content on one page on every Typst quill, so a
`<quill-keep>` pair a 0.123 document already holds keeps its run together where
0.123 let a page break split it.

**The content types gain an element member.** In Rust, `Container::Element
{ name, attrs, instance }`. In WASM, `ContentContainer` gains `{ container:
"element"; attrs: ElementAttrs; instance?: number }`, where `ElementAttrs` is
`{ $name: string; [attr: string]: string }`: the element's name sits in the bag
under `$name`, beside its attributes.

|---|---|---|
| A `</u>` closes the innermost open `<u>`, one carrying an attribute included, and never a `**`; a `<u>` left open where its text ends drops and warns `parse::dropped_construct` (`u`), where it underlined the rest of the body | rendered output, imported content, `Parsed.warnings`, `doc.warnings` | Close each `<u>` in the text it opens in |
| A `<u>` tag exports outside the `**`, `_` and `~~` delimiters at its position, and an underline crossing one of them as one pair the delimiters cross | `Document::to_markdown`, `toMarkdown`, `to_markdown` | None |
| A line holding only tags after a table's rows ends the table, where a type 7 tag added an empty row | rendered output, imported content | None |
| A fenced block holding `<!-- a --> b` keeps its line | rendered output, imported content | None |
| Text after a block nested in a tight list item opens its own line, where it joined the block's last line | rendered output, imported content | None |
| A raw tag or footnote-shaped definition in a body warns `parse::dropped_construct` at the body; `quillmark validate` fails a quill whose `example.md` holds one, as `cli::example_not_clean` | `Parsed.warnings`, `doc.warnings`, CLI | Drop the markup, or let the warning stand |
| A one-shot render no longer carries `doc.warnings` (parse and `conform::*`) ahead of its own | WASM `engine.render`, Python `Quillmark.render`, `RenderResult.warnings` | Read `doc.warnings` after a load, and a revise's `warnings` after a revise |
| `from_markdown` returns `Imported`; `diff_import` returns the warnings third | `quillmark_content` | Take `.content`; bind the third element |
| A revise returns `Revised { delta, warnings }`, `#[must_use]`; `TypedWriter::add_card` returns `Vec<Diagnostic>` | Rust `Card`, `CardMut`, `TypedWriter`, `CardWriter` | Take `.delta`; read or bind `.warnings` |
