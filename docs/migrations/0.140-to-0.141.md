# 0.140 → 0.141 — `multiline:` refused, and `multiline` gone from the schemas

## `Quill.yaml`

A `text` or `richtext` field declaring `multiline:` fails to load as `quill::field_parse_error`, where it loaded with a `quill::deprecated_multiline` warning; the hint names `shape:`. Declare the shape it meant:

| Was | Now |
|---|---|
| `{ type: text, multiline: false }` | `{ type: text }` |
| `{ type: text, multiline: true }` | `{ type: text, shape: lines }` |
| `{ type: richtext, multiline: false }` | `{ type: richtext }` |
| `{ type: richtext, multiline: true }` | `{ type: richtext, shape: blocks }`, or `shape: lines` where the field holds lines and no list, heading or table |

`quill::deprecated_multiline` is no longer emitted.

## Schemas and bindings

| Break | Surface | Action |
|---|---|---|
| A field's declaration view no longer carries `multiline: true` beside `shape` | `schema()` in Rust, WASM and Python, `quillmark schema`, WASM `QuillFieldSchema` | Read `shape`: absent is one line, `"lines"` or `"blocks"` more than one |
| The transform schema no longer carries `quillmark:multiline: true` beside `quillmark:shape`, and the content body carries `quillmark:shape: "blocks"` | Rust `build_transform_schema` | Read `quillmark:shape` |
| `QUILLMARK_MULTILINE_KEY` is removed | `quillmark-core` Rust API | Use `QUILLMARK_SHAPE_KEY` |
| `docs/schemas/quill.schema.json` refuses `multiline` | Editors validating `Quill.yaml` | Declare `shape:` |
