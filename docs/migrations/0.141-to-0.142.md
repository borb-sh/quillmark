# 0.141 → 0.142 — numbers resolve by the YAML 1.2 core schema

## Document Markdown

An unquoted value resolves by the YAML 1.2.2 core schema. A decimal integer with an optional sign, an unsigned `0o` octal or `0x` hexadecimal, or a float is a number: `0012` is the integer 12, `1.50` the float 1.5 and `0x1F` the integer 31, where 0.141 held each as the text written. A `text` field prints `12` for `0012` and `1.5` for `1.50`; quote a value whose digits are text, as `zip: "02134"`. YAML 1.1's `0b11` and `1_000`, `0X1F`, `0O17` and a signed `-0x1F` are strings, so a `number` or `integer` field refuses them as `validation::coercion_failed`, where 0.141 read 3, 1000 and 31. A document holding such a value hashes differently from the same markdown parsed by 0.141.

| Break | Surface | Action |
|---|---|---|
| A plain `0012`, `1.50` or `0x1F` is a number, not the string written | a parsed document's field values in Rust, WASM and Python | Quote the value where its text is wanted |
| A plain `0b11`, `1_000`, `0X1F` or `-0x1F` is a string, and a `number` or `integer` field refuses it | document markdown | Write the number in a core form: `3`, `1000`, `0x1F`, `-31` |

## Writing a document

The typed writer reads a string for a `number` or `integer` field by the same core schema. `set('n', '0x1F')` and `set('n', '0o17')` store 31 and 15; `0b11`, `1_000`, `0X1F` and `-0x1F` are refused as `edit::field_coercion_failed`, where 0.141 stored 3, 1000 and 31.

| Break | Surface | Action |
|---|---|---|
| `0b11`, `1_000`, `0X1F` and `-0x1F` are refused for a `number` or `integer` field | `TypedWriter::set` and `CardWriter::set` in Rust, WASM and Python | Pass the number, or a string in a core form |
