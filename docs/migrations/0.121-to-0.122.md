# 0.121 → 0.122 — a comment keeps the slot the YAML gives it, and every tag warns at its node

## A comment keeps the slot the YAML gives it

The break that needs the most care is the one nothing reports: **a comment the
pre-scan misplaced re-emits at the slot the YAML gives it.** 0.121 worked out a
card-yaml block's structure from indentation, so some spellings moved a comment
to another line, or dropped it, while every value read correctly. 0.122 reads
each comment's container and slot from the YAML parser's events, and
`to_markdown` writes it back there. No diagnostic fires, and the values are
unchanged; the canonical markdown moves, so a hash over it recomputes.

| Break | Surface | Action |
|---|---|---|
| A comment in one of the spellings below re-emits at its own slot, where it moved or dropped | `to_markdown` output, hashes over it | None. Find the documents it touches as below |
| A sequence item carrying a trailer beside its first key's emits `- # item` with the key on the line below, where the key's trailer moved under the first field's value | `to_markdown` output | None |
| `parse::unsupported_yaml_tag` fires on every tagged node, at its own path | diagnostics | Expect warnings on tags inside flow collections, on sequence elements and on keys, and match the corrected paths |
| A column-zero key outside the field grammar fails as `parse::invalid_structure` naming the field, where `og:title: "Issue #5"` failed as a YAML error | diagnostics | Rename the field |
| A quoted top-level key keeps its source position on emit, where it moved to the end | `to_markdown` output | None |
| A block whose comments and tags sit under more key-path bytes than 64 per byte of the block, plus 64 KiB, fails as `parse::invalid_structure` | diagnostics | Shorten the keys above the comments |
| `Payload::nested_comments` lists a parsed block's comments in emit order, and a trailer on a sequence item's first key below a bare dash is the item's | Rust, storage DTO of a re-parsed document | None, unless a consumer compared the list to 0.121's |

The spellings that moved a comment:

```yaml
to:
# lead
- name: a # c1
  # inner
  rank: 1
classification:
  value: CUI
# note
  controlled_by: SAF/AA # tail
l:
  - - x # c1
    - w # c2
note: first
  key:value # z
```

- **A sequence at its key's column**, as PyYAML and kubectl write it: 0.121
  moved `# lead` after the sequence and dropped `# c1` and `# inner`. Nested
  inside a mapping (`o:\n  k:\n  - a # c`), it moved `# c` onto the next key.
- **A comment indented less than its block**: 0.121 moved `# note` after the
  whole block and dropped `# tail`.
- **A compact nested sequence**: 0.121 moved `# c1` onto the outer dash line and
  `# c2` to the head of `l`.
- **A trailer on a plain scalar's continuation line**: 0.121 dropped `# z`.

A document stored through the DTO keeps the comments its 0.121 parse read, and
re-emits them where 0.121 did. Re-parse it from its markdown source to place
them by the YAML.

## Every tag warns at its node

A tag on any node warns as `parse::unsupported_yaml_tag` at that node's path:
a sequence element (`main.notes[0]`), a node inside a flow collection
(`main.flow[1]`), a key, a value after an anchor or on the line below its key.
0.121 warned only for a tag opening a block key's value on the key's own line,
and named a wrong path where a sequence sat at its key's column (`main[3].name`
for `main.to[0].name`), a comment sat left of its block
(`main.controlled_by` for `main.classification.controlled_by`) or a dash line
held only an anchor (`main.l.y` for `main.l[0].y`). The code is unchanged and
the value is kept as read, as before.

## Finding what moves

Comment moves leave no diagnostic. Parse each document's markdown source under
0.121 and under 0.122, emit it with `to_markdown`, and diff: only documents with
a comment in the spellings above change. Sequences at their key's column, the
spelling PyYAML and kubectl write, narrow from:

```bash
grep -rnE -B1 '^[[:space:]]*- ' <your documents> | grep -E ':[[:space:]]*$'
```

then compare the indentation of each `key:` line with the dash below it.
