# 0.137 → 0.138 — a newline is a line break, and a text field declares a `shape`

## What a document prints

A newline inside a paragraph is a line break, where it was a space. A blank line is a paragraph break, as before. This holds in the document body and in every `richtext` value read from Markdown. The CommonMark spellings of a line break, two trailing spaces or a trailing `\`, and an inline `<br>` read as they did, so text that used them is unchanged.

- **A body hard-wrapped in its source prints its wraps.** A paragraph typed across several source lines printed as one flowing paragraph and now breaks at each newline. Join the lines of a paragraph that should flow. A heading, a table cell and a footnote's text still read a newline as a space.
- **Export writes a line break as a newline**, where it wrote a trailing `\`. A consumer that hands exported Markdown to a CommonMark renderer reads those breaks as spaces.
- **A paragraph and a `: ` line under it are two lines**, where they were one line joined by a space.

A stored row loads as it was saved: `quillmark/document@0.135.0` is still the storage tag, and a value stored as content is never reread. The body is stored as content. A field value is stored as content once a quill has written it, through `Quill::conform` or the typed writer, and as its Markdown string in a row saved from an unbound `Document::parse`. A string is read again on the next bound load, under this release's rule. A host that stores rows from an unbound parse conforms them against their quill on the old release before taking this one, or accepts that a folded newline in a stored field becomes a line break.

## `Quill.yaml`

A `text` or `richtext` field declares how much it holds with `shape`, where it declared `multiline`.

| `shape` | Holds |
|---|---|
| `line` (the default) | one line |
| `lines` | lines and paragraphs of lines |
| `blocks` | lines, and headings, lists, quotes, code and tables (`richtext` only) |

| Was | Now |
|---|---|
| `{ type: text }` or `multiline: false` | `{ type: text }` |
| `{ type: text, multiline: true }` | `{ type: text, shape: lines }` |
| `{ type: richtext, multiline: false }` | `{ type: richtext }` |
| `{ type: richtext, multiline: true }` | `{ type: richtext, shape: blocks }` |

`multiline:` still loads this release with the meaning in the table and one `quill::deprecated_multiline` warning per quill. A `richtext` no longer has to declare either key. `shape` and `multiline` that disagree are a load error, and so is `shape: blocks` on a `text`.

`shape: lines` on a `richtext` is new: formatted lines with no block structure, for an address, a signature block or a list of recipients. In a `line` or a `lines` field, block syntax prints as typed: `1. Alpha` is the text `1. Alpha` and `- Bravo` the text `- Bravo`, where a `multiline: true` field read them as lists. A field whose values are lines moves to `shape: lines`, and a plate that split its paragraphs into lines reads the line breaks the value now holds.

A one-line `richtext` reads a newline in its Markdown as a space, as it rendered before. A value written as content that holds a block a `lines` field does not is refused as `validation::not_lines`, and a seed that does as `quill::seed_not_lines`.

## Schemas and bindings

| Break | Surface | Action |
|---|---|---|
| `FieldType::Text { multiline }` and `FieldType::RichText { multiline }` are `{ shape: Shape }` | Rust | Match on `shape`; `Shape::Line` is the old `false` |
| `ValidationError` gains `NotLines` | Rust | Add an arm to an exhaustive match |
| `quillmark_content::view::layout` is removed | Rust | Read a table's widths, alignments, header rows and spans from `quillmark_content::table::Layout::of`, and a cell's text and marks from `view::cell` |
| A field's schema carries `shape`, and its JSON Schema `quillmark:shape`, when the shape is not `line`; the body's JSON Schema carries `quillmark:shape: "blocks"` | Rust, JS, Python | Read `shape`. `multiline: true` and `quillmark:multiline: true` are still emitted beside it this release, for both `lines` and `blocks`, and leave in a later one |
