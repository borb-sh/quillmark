# 0.124 → 0.125 — task lists and footnotes

Two GitHub Flavored Markdown constructs join the content: a task list item and
a footnote. Markdown that spelled either imported as something else in 0.124,
so each section below is a change nothing reports, and the table closing the
guide lists every break.

## Task lists

**`- [ ] open` and `- [x] done` render a box before the item's text, ticked
for `[x]`, where 0.124 rendered the brackets as text.** The item stores the
mark as its `checked`, `true` or `false`, and its text without it. A Typst
plate draws the box, or replaces it through the helper's `tasks` state:

```typst
#import "@local/quillmark-helper:0.1.0": data, tasks

#tasks.update(_ => (done, body) => if done { strike(body) } else { body })
```

To keep the brackets as text, escape the first: `- \[ ] open`. Export escapes
a stored item text opening `[ ] ` or `[x] `, so it re-imports as text.

## Footnotes

**`text[^1]` with a `[^1]: The note.` definition renders a footnote, where
0.124 read the definition as a link reference definition**, which dropped its
line and made every `[^1]` a link to `The note.`. The reference stores as a
`footnote` island at its place in the paragraph, holding the note as one table
cell, `{text, marks}`; a note cited twice prints twice. Export numbers the
references `[^1]`, `[^2]`, … in reading order and writes each definition after
the body.

A note is one passage. What it cannot hold drops and warns
`parse::dropped_construct`:

- a heading, list, code block, quote, table or rule inside a note keeps its
  text as lines of the note and warns `footnote[list]` and the like;
- a definition nothing references, a second definition of one label, and a
  reference inside a table cell or a note warn `footnote`.

An acroform quill declines a footnote as it declines every construct but the
paragraph: `backend::declined_construct` at render, and
`validation::declined_construct` from `validate`.

## Stored rows

**The storage tag is `quillmark/document@0.125.0`**, the first that can hold a
task item's `checked` or a `footnote` island. A row under an older tag loads as
before, and its content does not re-import, so text it stored as `[ ] open`
stays text. A save rewrites it under the new tag, so a hash over stored bytes
recomputes once, though nothing else in the row moves. A 0.124 build refuses a
row from then on, as a build too old for its tag.

## Every break

| Break | Surface | Action |
|---|---|---|
| A task list marker renders a box, ticked for `[x]`, and imports as the list item's `checked`, where it was text | rendered output, imported content | Escape the bracket, `\[ ]`, to keep the text |
| A footnote reference and its definition render a footnote and import as a `footnote` island, where the definition defined a link | rendered output, imported content | None |
| A definition nothing references, a second definition of one label, a reference in a table cell or a note, and a block inside a note warn `parse::dropped_construct` (`footnote`, `footnote[<block>]`) | `Parsed.warnings`, `doc.warnings`, revise warnings | Drop the construct, or let the warning stand |
| An acroform render declines a footnote under `backend::declined_construct`, and `validate` warns `validation::declined_construct` | acroform session warnings, `RenderResult.warnings`, `Quill::validate` | None |
| `IslandType` gains `Footnote`, `BlockConstruct` gains `Footnote`, `Dropped` gains `Footnote` and `NoteBlock`, and `Container::ListItem` gains `checked`; `StoredDocument` gains `V0_125_0`, and `STORAGE_V0_125_0` is the current tag | Rust | An exhaustive `match` adds the arms; a `ListItem` literal sets `checked: None` |
| `ContentIsland` gains a `footnote` member, `props: FootnoteProps`, and a `list_item`'s `attrs` gain an optional `checked` | WASM | A `switch` over `type` handles `footnote` |
| A save writes `quillmark/document@0.125.0`, and a 0.124 build refuses the row from then on | stored documents | None to load; a hash over stored bytes recomputes |
