# 0.119 → 0.120 — a matrix member is held by being present, an open matrix admits added items, and a table's container column is `quill::table_column_not_leaf`

The break that needs the most care is the one nothing reports: **a matrix member
spelled as a mapping naming no `held` flips from unticked to ticked.** The value
is well-typed under both readings, so no type checker, no load error and no
diagnostic fires — the page prints a ticked box, and that member's columns with
their answers, where it printed an unticked one. The same flip reaches a
`Quill.yaml` `seed:` or array `default:` that spells a member that way.

The loud break is wider: **a member mapping storing `held` at all fails
validation as `validation::held_stored`, and the render with it.** 0.119's strict
write stored every bare tick as `{held: true}` — `writer.set` on any matrix, and
`quill.parse` / `conform` and card seeding on a matrix with a content column — and
the editor spelled `held` on every member it touched, so most stored documents
holding a tick carry one. A `Quill.yaml` literal storing `held` fails to load:
`quill::seed_held_stored` in a `seed:`, `quill::default_held_stored` in a
`default:`. [The section below](#a-matrix-member-is-held-by-being-present) says
how to find both.

The other break no type checker reports: **a `ui.layout: table` column that is
not a leaf is refused under a new code.** The refusal, its trigger and its
message are unchanged; only the code moves, so a consumer matching the old
string stops matching. `flat` is `ui.layout`'s word for a typed dictionary drawn
without a frame, and the column check names what it tests, `FieldType::is_leaf`.

| Break | Surface | Action |
|---|---|---|
| A matrix member spelled `{ detail: X }` — a mapping naming no `held` — is held, where it was unheld | document YAML, `Quill.yaml` `seed:` and `default:`, rendered output | Remove every such member meant to be unticked. Nothing reports this one: find it as below |
| A matrix member mapping storing `held` fails validation as `validation::held_stored`, and the render with it | document YAML, stored documents, diagnostics | Delete `held: true`; remove a member stored `held: false`, whose answers go with it |
| A `Quill.yaml` `seed:` or `default:` storing `held` fails to load as `quill::seed_held_stored` / `quill::default_held_stored` | `Quill.yaml` | The same edit, in the literal |

| The strict write rests a bare tick as `true` and an empty mapping as `true`, where it wrote `{held: true}` | stored documents | None: the new rest is what the previous row asks for. Re-baseline a byte snapshot of a conformed document |
| A matrix's blueprint `# e.g.` line spells its member without `held: true`, and an open matrix's shows a `new_item` added item | `blueprint()` output | Re-baseline anything asserting on blueprint bytes |

## A matrix member is held by being present

A document ticks a member by writing it. The rule has one carrier, the member's
presence, and the document never stores `held`:

```yaml
qualifications:
  flight_cc: true                  # held, unchanged
  cyber_200: {}                    # was unheld; now held
  dodin_ops: { detail: "2024" }    # was unheld; now held
  dco: { held: true, detail: X }   # was held; now validation::held_stored
  sq_cc_candidate: false           # not held, unchanged
```

0.115 retired the reading that ticked a mapping naming no `held`, because it
overrode the ladder for one key: `{ detail: X }` and `{ held: false, detail: X }`
were two mappings one key apart meaning opposite ticks. Presence has no second
key to disagree with it. A stored `held` is refused whichever value it holds:
`false` under a present member contradicts the presence that holds it, and
reading it either way is a guess. A `held: null` is absent, as at every type.

What moves with it:

- **An unticked member keeps nothing.** Unticking removes the member, and its
  columns go with it. An editor that wants a retick to restore them keeps them
  itself.
- **An empty mapping ticks.** A member is the one namespace whose `{}` is an
  answer. An editor clearing a held member's last column leaves it held; the
  strict write rests it as `true`.
- **The blueprint teaches less.** Its `# e.g.` line no longer spells the
  `held: true` a mapping needed to tick.

Two finds. The loud one: before upgrading, every stored `held:` under a matrix
member is the edit; after, `quill.validate(doc)` names each as
`validation::held_stored` at its path, and a quill storing one names it at load.
Delete `held: true`, and remove each member stored `held: false`.

The silent one is a mapping naming no `held` that was meant to be unticked,
which only a hand or a model writes, in a document or in a quill's `seed:` or
`default:`. Inline spellings narrow from:

```bash
grep -rn ':[[:space:]]*{' <your documents and quills> | grep -v held
```

A block mapping under a member id needs the roster: for each matrix field in
your quills, search its member ids and read the lines under each hit.

## An open matrix admits items a document adds

`open: true` on a matrix lets a document add items beside the roster, each keyed
by a snake_case id and carrying a `title`:

```yaml
qualifications:
  flight_cc: { detail: UMS Flt/CC }
  wing_ig: { title: Wing IG, detail: 81 TRW }
```

Nothing changes for a closed matrix. On an open one:

- The plate receives the roster in roster order, then each added item sorted by
  id, `{held: true, title, …columns}`. An added item's `title` is a cell with an
  address, so `ink(m).title` exists on an added item alone.
- A key outside the roster with no `title`, or one no snake_case id spells, is
  `validation::enum_violation` with `open: true`.
- The transform schema carries the added item as the matrix node's
  `additionalProperties`, and `schema()` emits `open: true` (WASM
  `QuillFieldSchema.open`).
- An acroform quill declaring one fails to load as
  `quill::open_matrix_unsupported`.
