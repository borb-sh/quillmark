# 0.130 → 0.131 — font family in richtext, a host font library, and tables as pipes or HTML

A writer sets a run of richtext in a font family, spelled in markdown as a
`qm-span` pair, and an app hands the engine a font library of its own to
choose families from. A table writes as a GFM pipe table or as HTML, which
spells merged cells, and its layout leaves the `qm-*` carrier: **`qm-table`
and `qm-cell` no longer spell a table's layout**, so markdown 0.130 exported
with either loses the table's widths, placement, header row setting and cell
alignment when it is read back. The sections up to Tables are the changes no
type checker reports; the table closing the guide lists every break.

## Stored rows

**A row holding a `font_family` mark, an element named `table`, a merged
table cell or a table `head` 0.130 cannot draw saves under
`quillmark/document@0.131.0`**, the first tag that can hold them: 0.130 refuses
the element as corrupt and draws the rest wrong. Every other row saves under `@0.129.0` as
before, byte for byte, so a 0.130 build reads it and a hash over its bytes
holds. A 0.130 build refuses a row under the new tag, as a build too old for
it, so deploy every reader before a writer saves one, and a writer rolled back
to 0.130 cannot open the rows 0.131 saved under it.

`Document.currentStorageVersion()` (WASM) and
`Document.current_storage_version()` (Python) return the newest tag,
`@0.131.0`, though most rows still save as `@0.129.0`. A check that treats any
other tag as a version mismatch now flags rows this build wrote: let
`fromStored` decide, and read the tag only once it throws.

## Markdown

**`<qm-span family="Carlito">text</qm-span>` inside a line sets its text's
family, where 0.130 dropped the tags and warned `parse::dropped_construct`
(`qm-span`).** Markdown that spelled one now imports with a font mark and
renders in that family. Pairs nest, and the outer family resumes past an inner
pair. A character holds one family, so export writes nested pairs back side
by side, and a `MarkOp::Add` of a family replaces the family under its range.
An attribute other than `family` drops alone and warns
`qm-span[<name>]`. A tag setting no family, or a pair left open, drops and
warns `qm-span` as before. A `qm-span` tag line, which 0.130 read as an
element named `span` around the blocks below it, drops and warns `qm-span`, and
the blocks stay.

[Markdown Syntax](../authoring/markdown-syntax.md#font-family) has the full
rules.

## Rendering

A Typst render sets a font run's family ahead of the font list in force, so a
character the family lacks falls through to the surrounding font. A family the
host library lacks keeps the surrounding font and warns
`typst::unknown_font_family` once per family and field, at the field's path,
on every compile. Code spans and equations keep their own font. An acroform
render ignores the mark.

An app adds fonts through the engine: `Engine::with_fonts(files)`, the
`fonts` option of `new Engine(..)` in JavaScript, `Engine(fonts=..)` in
Python, and `--font` on `quillmark render` and `quillmark workspace`. The
embedded Roboto still loads only for a quill shipping no fonts. A file other
than `.ttf`, `.otf`, `.ttc` or `.otc` fails the engine with
`engine::font_unsupported`, and one holding no face Typst reads with
`engine::font_unreadable`. A font run sets only a family the library holds: a
quill's own fonts and the embedded Roboto set the plate, never a run. A
library face sets only marked text: a plate naming its family, a missing bold
or italic, and glyph fallback never reach it, so a document without font
marks renders as it did on 0.130.
`engine.fontFaces(quill)` lists the library's faces, with their bytes.

## Tables

### `qm-table` and `qm-cell`

**`<qm-table widths="2 1">` around a pipe table is an ordinary element named
`table` around a bare table, which a quill renders as if the tags were absent,
warning `typst::unregistered_element`; `<qm-cell align="right">42</qm-cell>`
in a cell imports `42` and warns `qm-cell`.** A host that keeps documents as
markdown converts
each table holding either: import it on 0.130, which still reads the carrier,
and export the content on 0.131, which writes HTML, or rewrite it by hand.
0.130 drops an HTML table, so the rewritten markdown needs 0.131:

```markdown
<table widths="2 1" align="center">
<thead>
<tr><th>Item</th><th>Qty</th></tr>
</thead>
<tbody>
<tr><td>Total</td><td align="right">42</td></tr>
</tbody>
</table>
```

A `headless` wrapper is a table with no `<thead>`, its rows `<td>` cells in a
`<tbody>`. A pipe table's delimiter row spells its column alignment, which
HTML spells `aligns="none right"` on `<table>`. Loading a stored row on 0.131
and exporting it writes this spelling for every table that needs it.

### Export

**`to_markdown` writes an HTML table for a table holding `widths`, a
placement, a cell's `align` or `valign`, a span, or more or fewer than one
header row**, where 0.130 wrote a pipe table inside a `qm-table` wrapper with
`qm-cell` pairs. Every other table writes as pipes, as before, and a `<table>`
holding nothing pipes cannot write re-exports as pipes. A consumer reading
exported markdown with its own parser reads an HTML block for such a table:
GitHub draws its grid and spans and shows the markdown in its cells as
written.

### Import

**An HTML block opening `<table>` imports as a table**, where 0.130 dropped
it and warned each of its tags, `table`, `tr` and `td` among them. Markdown holding a raw HTML table renders it now.
What the subset does not hold warns `parse::dropped_construct`:

- `table` for a table its block ends before its `</table>`: a blank line
  inside a table ends it, and the rows after it drop as an HTML block of their
  own, warning their tags;
- `table[row]` for a row too short for the table, which is as wide as its
  widest row;
- `table[text]` for text outside every cell, and a tag's name, such as
  `caption`, for any other tag;
- `table[size]` for the rows past `MAX_TABLE_CELLS` (100 000) slots, rows
  times columns, which drop, a pipe table's as an HTML table's;
- `<tag>[<attr>]`, such as `td[nowrap]` or `table[widths]`, for an attribute
  the subset does not read or a value outside its spelling; `border`,
  `class`, `scope` and `style` drop without a warning.

What follows a `</table>` in its block, on its line or the next, reads as
markdown of its own, so prose written tight under a table imports.
`qm-table[<attr>]` and `qm-cell[<attr>]` no longer occur.

### Stored rows

**A table's header rows are `head`, a count, and a stored `headless: true`
normalizes to `head: 0`.** A row holding `headless: true` loads as before and
rewrites once when saved, so a hash over its stored bytes recomputes; a
table moves no row off `quillmark/document@0.129.0`. A 0.130 build reading a
row 0.131 saved draws a `head: 0` table with a header row.

**A table whose grid pads past `MAX_TABLE_CELLS` slots is refused** as
`Invariant::TableTooLarge`, on load, on `overwrite` and on an island op, before
the mint pads it.

**A cell's `colspan` and `rowspan` span it**, where 0.130 carried them as keys
it did not name. Normalization settles each to what it can cover: empty cells
no other span covers, inside the grid and its head or body section. A span
past that stores shorter, and a covered cell's `colspan`, `rowspan`, `align`
and `valign` drop, so a host that stored either key under another meaning
reads it rewritten.

| An inline `qm-span` pair imports as a `font_family` mark, where it dropped and warned `qm-span` | imported content, rendered output, `Parsed.warnings` | None |

| A font run in a family the host library lacks warns `typst::unknown_font_family` | Typst session warnings, `RenderResult.warnings` | Supply the family, or treat the code as an error where a hard failure is wanted |
