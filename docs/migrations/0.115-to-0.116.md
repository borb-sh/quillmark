# 0.115 → 0.116 — a card-yaml payload that is not a mapping fails at its fence

The one break is a diagnostic code. Nothing that parsed stops parsing, and
nothing that failed starts to.

| Break | Surface | Action |
|---|---|---|
| A card-yaml payload that is YAML but not a mapping fails as `parse::payload_not_mapping`, where it was `parse::invalid_structure` on a card and `parse::missing_quill` on the root | diagnostics | Route on the new code. Read the fence's line off `location` |

## Breaking: a non-mapping payload has its own code

A column-zero `~~~` opens a card-yaml block whatever its info string, so code
fenced with tildes in a body reaches the YAML parser, where it usually reads as
a string. The failure carried no location and named neither rule nor fix. It is
now its own code, located at the opener's line, and its hint names the backtick
fence to write instead.

| A block holding | 0.115 | 0.116 |
|---|---|---|
| a string, number, boolean or sequence, as a card | `parse::invalid_structure`, `Invalid YAML in card block: expected a mapping`, no location | `parse::payload_not_mapping`, located at the opener |
| the same, as the root block | `parse::missing_quill` | `parse::payload_not_mapping`, located at the opener |
| an empty or null payload | an empty mapping | unchanged |

`args` carries `actual` (`string`, `number`, `boolean` or `sequence`) and, when
the opener has an info string, `info`: `python` for `~~~python`.

**Migrate:** a consumer routing the non-mapping case under
`parse::invalid_structure` or `parse::missing_quill` routes it under
`parse::payload_not_mapping`. To fix a document, change each tilde fence
around code to backticks: the diagnostic's line is the one to edit.
