# 0.115 → 0.116 — `!must_fill` is gone; a card of an undeclared kind, and a body under `body.enabled: false`, render and warn; an undeclared key warns; a card with no `$kind`, and a non-mapping card-yaml payload, fail at the fence

The break nothing reports on a stored row: **a value under a block-style
`!must_fill` is dropped on load.** A stored row carrying the marker loads with
that cell unanswered and no diagnostic, where 0.115 kept the value as a
placeholder; a markdown document drops it too, and warns
`parse::must_fill_dropped`. Read [`!must_fill` is removed](#must_fill-is-removed)
before a stored row saves under 0.116.

The break no error reports: **a document that failed to render now renders.**
A card whose `$kind` the quill does not declare, and body prose under
`body.enabled: false`, were fatal `validation::*` errors. Each is now a
`Warning`, on a one-shot render's `warnings` and from `quill.validate(doc)`,
and the render proceeds without the input. A pipeline that relied on the
render failing to catch these documents catches nothing: act on the two codes
below. On the CLI, `render` prints them, and `quillmark check --strict`
fails on them.

The rule behind it: a render fails only where the engine would have to invent
what the author wrote. Input no declaration claims displaces nothing, so it
renders and warns
([SCHEMAS.md § What blocks a render](https://github.com/borb-sh/quillmark/blob/main/prose/canon/SCHEMAS.md#what-blocks-a-render)).

A quieter one for plates: **a typed dictionary or table row carries `$ink`
and `$path` keys.** A plate that walks a typed dictionary's keys, compares one whole, or
spreads a row into a call sees one more entry. See
[Print with `ink`](#print-with-ink).

## `!must_fill` is removed

The marker said a cell held a placeholder rather than an answer, and the
schema half of `validation::must_fill` said a cell with no `default:` needed
one. Neither survives: `default:` is the value an unanswered cell renders and
nothing more, `?` moves the render floor and nothing more, and null ≡ absent
holds on every surface — `field: ""` and `field: null` differ in the value they
render and in nothing else.

**What loads.** A value under a block-style marker reads as a placeholder, not
an answer, so every reader drops it with the marker. Elsewhere only the tag
drops:

| Stored as | Loads as |
|---|---|
| `subject: !must_fill Example` | `subject:` (null) |
| `recipient: !must_fill` over a block sequence | `recipient:` (null) |
| `addr:` with `street: !must_fill Main` beneath it | `addr: {street: null, …}` |
| a stored row's field with `"fill": true` | the field, value null |
| a stored row's `nested_fills` path | that node, null |
| `$ext`/`$seed` content tagged `!must_fill X` | `X`, tag dropped, `parse::unsupported_yaml_tag` |
| `tags: [a, !must_fill b]`, a flow collection on one line or several | `[a, b]`, tag dropped, no warning |
| `- !must_fill Mr. Doe`, a bare `- ` element | `Mr. Doe`, tag dropped, no warning |
| `subject: &a !must_fill Example`, the tag after an anchor | `Example`, tag dropped, no warning |
| `!must_fill Example` on the line below `subject:` | `Example`, tag dropped, no warning |

The markdown reader warns `parse::must_fill_dropped` at the `path` of each
value it drops (`main.subject`, `cards.note[0].subject`). A stored row loads
with no report, and its first save under 0.116 writes the drop in for good.

Two routes left an answer under the flag. A value typed over a tag left on in
raw markdown stored as `fill: true`, since 0.115's `validation::must_fill`
warned without blocking. A 0.115 `insertCard` / `insert_card` of
`{...item, value}` carried the read item's `fill` onto the new value. Before a
row's first 0.116 save, list its flagged fields:

```sh
jq -r 'select(.schema != "quillmark/document@0.116.0")
  | [.main, (.cards // [])[]][]
  | (.payload.items // .frontmatter.items // [])[]
  | select((.type // .kind) == "field")
  | select(.fill == true or ((.nested_fills // []) | length > 0))
  | .key' row.json
```

Run it per row, so each key stays with the host's row id. A flagged value that
differs from the field's `example:` in the quill version the row pins is likely
an answer: keep it, and store it again after the upgrade. Searching a row's
text for `"fill":true` or `"nested_fills":[[` is a coarse prefilter only, since
a JSONB column may re-space it.

**What seeding makes.** A seed is a document nobody has answered: one card per
declared kind, each body empty, every field absent and rendering its
`default:` or blank. An `example:` shows in the blueprint's `# e.g.` line and
nowhere else, `body.example`'s included, and an editor may show that one as
the empty body's placeholder. `seed_card` commits the
document's `$seed` overlay for the kind, taken whole, over that.

```yaml
# 0.115 blueprint
recipient: !must_fill # array<string>
  - Mr. John Doe

# 0.116 blueprint
# e.g. [Mr. John Doe]
recipient: # array<string>
```

## A label is a top-level `title`

`ui` keys never reach the blueprint, so a label under `ui` was invisible to an
agent working from it, while a person names a field by that label. `title` sits
beside `description` on a field and on a card kind, and the blueprint prints it.

```yaml
# 0.115
card_kinds:
  indorsement:
    description: Chain of routing endorsements.
    ui:
      title: Routing indorsement

# 0.116
card_kinds:
  indorsement:
    title: Routing indorsement
    description: Chain of routing endorsements.
```

A template (`ui.title: '{heading}'`) has no replacement: a consumer labels an
instance from its own values, so field order decides which value leads. Drop
it, and declare first the field that names the instance. A row's
`items.ui.title` goes the same way.

## The render date

A document dated by the day it renders stores `today` in a `date` field, or its
quill declares `default: today`. The engine reads no clock: the host passes the
render date, and the field and a plate's `datetime.today()` both render as it.

```rust
let today: CalendarDate = "2026-03-14".parse()?;
let session = engine.open(&quill, &doc, today)?;
```

A Rust host passes its local date, read from its own clock and built with
`CalendarDate::new(year, month, day)`. The CLI takes `--today YYYY-MM-DD`;
`engine.open` / `engine.render` / `reader.resolve` take an optional trailing
`YYYY-MM-DD` string in JavaScript, and `engine.render` a `today=`
`datetime.date` in Python. Each defaults to the local date.

## What reaches the plate

A card whose `$kind` the quill does not declare keeps its place in `$cards`
with its `$kind` as authored, its fields verbatim and uncoerced, and no
`$body`. A plate that branches on the kinds it knows falls through on it, which
is what every fixture plate does. Every card carries `$kind`, so a bare
`card.at("$kind")` reads.

A body under `body.enabled: false` does not reach the plate, as before.

## An undeclared key warns

`quill.validate(doc)` warns `validation::unknown_field` at each key the schema
does not declare where it sits: a card field, a typed dictionary's property, an
array element's property, a matrix member's column, or a cell inside a variant
container that no world declares. The page is unchanged: the key still
crosses to the plate verbatim, except inside a variant container, whose wire
carries only the live world.

A strict consumer that reads an empty `validate`, or a one-shot render's empty
`warnings`, as done sees the new warning on any document carrying such a key.
That includes a key a plate reads through `data.at("logo", default: none)`
without declaring it: declare it in `Quill.yaml`, and the warning goes.

The hint names the likely fix, and `args` carry it. `container` and `variant`
mark a variant cell written beside its discriminant (`outcome: motion` with
`moved_by:` next to it rather than under it). `suggestion` names the declared
field a misspelled key most likely meant.

## A non-mapping payload has its own code

A column-zero `~~~` opens a card-yaml block whatever its info string, so code
fenced with tildes in a body reaches the YAML parser, where it usually reads as
a string. The failure carried no location and named neither rule nor fix. It is
now its own code, located at the opener's line, and its hint names the backtick
fence to write instead.

| A block holding | 0.115 | 0.116 |
|---|---|---|
| a string, number, boolean or sequence, as a card | `parse::invalid_structure`, `Invalid YAML in card block: expected a mapping`, no location | `parse::payload_not_mapping`, located at the opener |
| the same, as the root block | `parse::missing_quill` | `parse::payload_not_mapping`, located at the opener |
| an empty or null payload | an empty mapping | unchanged |

`args` carries `actual` (`string`, `number`, `boolean` or `sequence`) and, when
the opener has an info string, `info`: `python` for `~~~python`.

**Migrate:** a consumer routing the non-mapping case under
`parse::invalid_structure` or `parse::missing_quill` routes it under
`parse::payload_not_mapping`. To fix a document, change each tilde fence
around code to backticks: the diagnostic's line is the one to edit.

## A card with no `$kind` fails the parse

Every block after the root is a card, and a card names its kind. A block whose
payload is a mapping naming no `$kind` is a card missing its kind line, or
tilde-fenced code whose text reads as a mapping, and the parser cannot tell
which. It fails as `parse::missing_kind`, located at the opener's line, and
its hint names both fixes: add a `$kind:` line, or fence the code with
backticks. `args` carries `info` when the opener has an info string.

| A block after the root holding | 0.115 | 0.116 |
|---|---|---|
| a mapping with no `$kind`, an empty or null payload included | a card with no kind: `Document.parse` succeeds, and the render fails `validation::unknown_card` with `card: ""` | `parse::missing_kind`, located at the opener |

A stored card with no `$kind` loads: it folds into the body above it, its
fields and comments as an untagged code block and its body after them, so the
prose under it stays in place. Its `$ext` drops. The code block admits the
fields' text as any body does, so a bidi control or U+FFFC in a field value is
dropped. An island id the body above already holds is renumbered past the
highest `isl-{n}` in either body, and a comment anchor whose id it already
holds drops. Every later card moves up one index.

**Migrate:** a consumer that parsed such a document and waited for the render
to fail sees the parse fail instead. To fix a document, add the card's
`$kind:` line, or change the tilde fence around code to backticks. A consumer
keying state by card index finds the folded cards in the raw row before it
loads: a `cards` entry whose `payload.items` holds no `kind` item. A
`quillmark/document@0.81.0` card stores a `sentinel` in place of `payload`
and never folds.

## `paint` takes one scale

`paint` rasterized at `layoutScale × densityScale` and reported
`layoutWidth = widthPt × layoutScale` back, a number the caller computed to
pass in. It takes the product alone, backing-store pixels per point, as a
required argument, and returns `undefined`.

```ts
// 0.115
const r = session.paint(ctx, page, { layoutScale, densityScale });
canvas.style.width = `${r.layoutWidth}px`;
canvas.style.height = `${r.layoutHeight}px`;

// 0.116
session.paint(ctx, page, layoutScale * densityScale);
canvas.style.width = `${widthPt * layoutScale}px`; // or "100%" of a page box
canvas.style.height = `${heightPt * layoutScale}px`;
```

A call with no scale, or with an options object, throws
`backend::invalid_raster_scale` where the first painted at 1 and the second at
the options' product. A scale that is not finite and positive throws the same
code, where it threw an uncoded message.

The painter still reduces a scale that would put a side past 16384 px. A
consumer that read `clamped`, `effectiveDensityScale` or `pixelWidth` /
`pixelHeight` reads `canvas.width` / `canvas.height`, and the scale painted at
is `canvas.width / widthPt`.

## One raster ceiling

Core refused a raster past 16384² px of area (`MAX_RASTER_PIXELS`) and the
WASM painter clamped at 16384 px a side, a limit of its own. The side is the
one limit now, core's `MAX_RASTER_SIDE`, and `fit_raster_scale` is the
reduction `paint` applies. The side rule is the narrower of the two only for a
page long on one axis: a PNG export whose long side passes 16384 px at the
asked `ppi` fails under `backend::invalid_raster_scale`, where it rendered
while its area fit.

## Print with `ink`

`data`, each card, and each typed dictionary or table row carry a printable copy
of their fields, read with `ink(..)`. Its values are born in generated code, so
they keep their click target in an editor preview through a function
parameter, a loop variable, a destructuring, a `filter` or a package, where a
plate's own `#row.org` keeps it only as a direct read. Compute with the
dictionary, print its ink:

```typst
// 0.115: the owner's region, rebuilt from a hand-composed address
#for card in data.at("$cards") {
  if card.at("$kind", default: none) == "task" {
    field-region(card.at("$path") + "owner")[#card.owner]
    display(card.at("$path") + "due", "[year]")
  }
}

// 0.116
#for card in data.at("$cards") {
  if card.at("$kind", default: none) == "task" {
    ink(card).owner
    display(card, "due", "[year]")
  }
}
```

The 0.115 form still works. A `field-region` stays the tool for ink the plate
composes: a sentence, a banner, a computed total. What each field's ink is:
[Print with `ink`](../quills/editor-regions.md#print-with-ink).

The copy is an ordinary dictionary key, `$ink`, present with the dictionary's
address prefix `$path` wherever at least one of its fields has ink. A composed
value in a row loop claims its region through that prefix:
`field-region(row.at("$path") + "amount")[..]`. Where a plate treats a typed
dictionary as a map, skip both:

```typst
#for (key, value) in row.pairs().filter(((k, _)) => not k.starts-with("$")) { .. }
```

## A plate resolves paths from its own file

A Typst plate is loaded at its `plate_file` path in the quill, and every other
`.typ` file outside `packages/` beside it, so paths resolve as Typst resolves
them: a bare path from the file that names it, a `/`-rooted path from the quill
root. A plate declared as `tpl/layout.typ` loaded as `/main.typ`, so its
`"assets/logo.svg"` reached the quill's `assets/`; it now reaches
`tpl/assets/logo.svg` and fails `typst::file_not_found`.

```typst
// 0.115, plate_file: tpl/layout.typ
#image("assets/logo.svg")
// 0.116
#image("/assets/logo.svg")
```

A plate at the quill root resolves every path as it did. The plate can now
import the quill's modules (`#import "lib.typ": header`), where each such
import failed `typst::file_not_found`.

## `body.unsupported` is removed

A quill declared, per body, the block constructs its plate does not typeset,
and a body holding one drew `plate::unsupported_construct`. Nothing checked a
declaration against the plate, and no editor read it off the schema. The key is
now unknown, so a `Quill.yaml` still declaring it fails to load:

```yaml
main:
  body:
    unsupported: [rule]   # quill::invalid_body
```

Delete the key. A construct the plate does not typeset renders as nothing and
raises no warning, as an undeclared one already did. `usaf_memo` drops its
`unsupported: [rule]`, so a rule in a memo body warns no more.

`backend::declined_construct` is unchanged: the Typst backend still warns for
an image in a content field.
