# 0.136 → 0.137 — acroform option boxes are a radio group, and widgets of one schema field are one field

## What a filled acroform PDF holds

The breaks no type checker reports are in the stamped PDF. `Form.yaml` reads unchanged.

- **Boxes with an `option:` are one radio field.** The boxes binding one `enum` stamp as a single radio-button field named by the first box's `name`, where each was a checkbox field of its own. A viewer keeps them exclusive. The field's `/V` and each button's on-state are the enum value (`/green`), where a ticked box carried `/Yes`. A consumer reading the filled PDF by field name finds one field under the first box's name, and reads the answer from its `/V`.
- **Bound fields naming one `schema_field` are one field.** Its widgets are kids of a field named by the first entry's `name`, so a later entry's `name` is no longer a `/T` in the PDF. A consumer that looked up the second box of a value by its own name looks up the first one's.
- **`option: Off` is refused** as `acroform::invalid_option`, since `Off` names every button's off-state. Bind that field without `option`, as a dropdown.

Regions and the canvas still key on `schema_field`, one region per widget, as before.

## Rust API

| Break | Surface | Action |
|---|---|---|
| `quillmark_pdf::FieldType` gains `Radio { on }` | Rust | Add an arm to an exhaustive match: a radio button draws and toggles as a checkbox does, under its own on-state |
| `stamp` stamps `FieldSpec`s sharing a `name` as one field with a widget for each, where it wrote two fields of one name | Rust | Give specs that are separate fields distinct names. Specs of one field must agree on type, value, face, size, justification and cap, or `stamp` refuses them as `pdf::conflicting_field`; a radio button whose `on` is empty or `Off` is refused as `pdf::bad_on_state` |
